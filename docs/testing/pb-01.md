# PB-01 acceptance cases

Run from the repository root with Python 3:

```console
python -m unittest discover -s tests -v
```

| Case | Expected evidence | Validation |
| --- | --- | --- |
| Stack and deployment | ADR chooses Python/FastAPI, Streamlit, pandas/NumPy, scikit-learn, SQLAlchemy/Alembic, PostgreSQL and CLI jobs; defers Redis/Celery | Manual ADR review |
| Scope | NSE cash equities, cash funding, long-only, daily five-session horizon; separate intraday work | Manual scope review |
| Modes | Paper simulated, shadow read-only, live disabled; unknown modes must fail closed | Manual mode-table review; runtime checks deferred to implementation |
| Ownership | Every proposed domain has responsibilities; model/UI cannot bypass independent risk | Manual boundary review |
| Claims | No profit guarantee; illustrative limits and 5% soft threshold explicitly qualified | Manual scope review |
| Navigation | All local Markdown file links resolve inside the repository | Automated documentation integrity test |

The documentation test checks navigation, not trading safety. Runtime mode
enforcement, PostgreSQL atomicity and execution faults require later behavioral
tests against implemented services. Architecture review covers the acceptance
criteria above; no external data or broker credentials are needed.
